# v0.3.0 品牌与产品认知建立开发规格

> 状态：已确认并实现
> 范围：新建品牌、添加产品/服务、异步分析、一次审核确认  
> 不包含：材料解析、内容生成、GEO 检测、偏差分析和持续运营

## 1. 本版本要完成的结果

用户完成首次流程后，系统应具备：

- 一个已保存的核心品牌；
- 至少一个已保存的产品或服务；
- 一份待确认或已确认的品牌认知六要素洞察；
- 每个产品或服务各一份待确认或已确认的 BFABEWW 洞察；
- 一次统一审核确认记录；
- 可供后续品牌监测和产品检测读取的当前认知基准。

结构化表单内容构成当前版本的事实档案。AI 只形成认知洞察，不生成营销内容，不反向修改事实字段。

## 2. 最终流程

```text
新建品牌
  ↓
填写品牌基本信息，可上传品牌资料
  ↓
添加至少一个产品或服务
  ↓
填写产品信息，可上传产品资料
  ↓
选填竞品，可直接跳过
  ↓
点击“完成并开始分析”
  ↓
分析前预检
  ├─ 未通过：定位到缺失或错误字段，补充后重新提交
  └─ 通过：保存数据、固定输入快照、创建后台任务
  ↓
后台异步执行品牌六要素和产品 BFABEWW 分析
  ↓
同一页面输出品牌及全部产品洞察
  ↓
客户修改、审核并一次确认
  ↓
建立当前品牌和产品认知基准
```

首次创建批次中，品牌和所有已添加产品应一起通过预检、一起分析、一次确认，不引入部分确认流程。

## 3. 分析前预检

### 3.1 执行方式

不增加独立预检页面。用户点击“完成并开始分析”时执行：

1. 前端先做必填和格式校验，立即显示字段级错误；
2. 服务端用同一套规则再次校验，服务端结果为准；
3. 未通过时不创建分析任务，已经填写的内容继续保留；
4. 页面按“品牌、产品、竞品”分组展示错误，并回到第一个错误字段；
5. 通过后一次保存品牌、产品和竞品，固定本次输入快照并创建异步分析批次。

草稿保存和开始分析是两个标准：品牌只有名称时可以保存草稿，但不能开始分析。

### 3.2 品牌最低标准

必须同时具备：

- 品牌名称；
- 符合公开行业标准的行业编码和名称；
- 能说明“品牌是什么、主要提供什么”的品牌简介。

只有名称、只有行业，或只有名称加行业，均判定为信息不足。其他六要素输入允许选填；某个要素缺少事实时，该要素输出“信息不足”，不得编造。

### 3.3 产品或服务最低标准

每个已添加的产品或服务必须同时具备：

- 名称；
- 类型：产品或服务；
- 能说明“具体提供什么”的简介；
- 在“核心特点、优势、应用场景、可解决问题”中至少填写一项。

其他判断规则：

- 至少添加一个产品或服务；
- 同一品牌下产品名称不得重复；
- 网址如填写，必须是有效的 `http` 或 `https` 地址；
- 不用字符数量代替信息质量，不让 AI 在预检阶段做主观评分；
- 证明依据、定量信息和应用限制允许为空，对应洞察可输出“信息不足”。

### 3.4 竞品与资料的预检标准

- 竞品整体选填，可以不添加并直接跳过；
- 空白竞品行忽略；填写了说明但没有名称时提示补充名称；
- 竞品不参与品牌认知六要素分析；
- 资料上传完全选填，不影响预检是否通过；
- 本版不读取资料正文，因此资料内容不能作为模型事实输入。

## 4. 输入字段

### 4.1 品牌字段

| 字段 | 要求 | 当前实现处理 |
| --- | --- | --- |
| 品牌名称 | 必填 | 复用 `name` |
| 品牌简称 | 选填 | 复用 `shortName` |
| 行业编码 | 分析必填 | 新增 `industryCode` |
| 行业名称 | 分析必填 | `industry` 改为标准行业名称语义 |
| 行业路径 | 自动带出 | 新增 `industryPath`，保存层级路径 |
| 行业标准版本 | 自动带出 | 新增 `industryStandard` |
| 营销品类名称 | 选填 | 复用 `categoryName`，保留自由文本 |
| 品牌简介 | 分析必填 | 复用 `intro` |
| 官方网站 | 选填 | 复用 `website` |
| 服务市场 | 选填 | 复用 `serviceArea`，不再使用本地生活语义 |
| 核心受众 | 选填 | 复用 `targetAudience` |
| 品牌定位 | 选填 | 复用 `positioningStatement` |
| 核心场景 | 选填 | 新增 `coreScenarios` |
| 价值承诺 | 选填 | 新增 `valuePromise` |
| 品牌特质 | 选填 | 复用 `characteristics` |
| 信任依据 | 选填 | 复用 `trustProof` |
| 认知边界 | 选填 | 新增 `cognitionBoundary` |
| 其他信息 | 选填 | 新增 `otherInfo` |

`city`、`stores` 等现有字段只为旧数据兼容，不进入新建核心表单。

### 4.2 行业字段标准

行业选择使用国家统计局公开的《国民经济行业分类》GB/T 4754—2017（按第1号修改单修订），保存编码、名称、完整层级路径和标准版本。界面支持按名称或编码搜索。

“行业”和“营销品类”保持两个概念：行业使用标准选项，营销品类名称继续由用户自由填写，避免为了品类再引入一套复杂分类系统。

### 4.3 产品或服务字段

下列内容全部是用户输入项，不是 AI 预先生成的结论：

| 字段 | 要求 | 当前实现处理 |
| --- | --- | --- |
| 名称 | 必填 | 复用 `name` |
| 类型 | 必填 | `type` 收敛为产品或服务 |
| 简介 | 必填 | 复用 `description` |
| 目标客户 | 选填 | 复用 `audience` |
| 核心特点 | 选填 | 复用 `features` |
| 应用场景 | 选填 | 新增 `scenarios` |
| 优势 | 选填 | 新增 `advantages` |
| 可解决问题 | 选填 | 新增 `problemsSolved` |
| 定量信息 | 选填 | 新增 `quantitativeFacts` |
| 证明依据 | 选填 | 新增 `evidence` |
| 应用限制 | 选填 | 新增 `limitations` |
| 其他信息 | 选填 | 新增 `otherInfo` |

客户填写的“优势”属于事实输入或待验证主张。BFABEWW 需要判断它是否有特点、证据和比较依据支撑，不能原样当作最终 Advantage 结论。

现有 `price` 仅保留旧数据兼容，不进入 v0.3.0 新建表单；本产品不管理价格。

### 4.4 竞品字段

首版只保留：

- 竞品名称；
- 简要说明。

竞品可为产品 Advantage 分析提供比较背景，但不单独建立竞品认知，也不进入品牌六要素输入。

## 5. 资料功能边界

本版资料能力只有四项：

- 上传并保存原文件；
- 按品牌或具体产品记录归属；
- 静态展示文件名、类型、大小、上传人和上传时间；
- 下载和删除。

本版明确不做：

- PDF、DOCX、TXT 等正文解析；
- 事实抽取、拆分、去重和归一；
- `factCount` 或“提取事实”展示；
- 将资料正文自动送入认知分析；
- 将“上传成功”显示为“知识已生效”。

用户状态只需要“上传中、已上传、上传失败”。现有附件表可继续使用，仅补充可空的产品归属；不新增材料解析表和解析任务。

## 6. 异步认知分析

### 6.1 固定输入

开始分析时保存：

- 品牌结构化字段快照；
- 本次每个产品的结构化字段快照；
- 选填竞品快照；
- 模型版本和提示词版本；
- 发起人和发起时间。

分析运行期间再次修改表单，不改变正在运行的结果。失败重试继续使用原快照；如需使用新输入，应由用户再次点击“更新洞察”。

### 6.2 输入隔离

- 品牌六要素只读取品牌结构化字段，不读取产品或竞品；
- 每个产品 BFABEWW 读取自身字段和适用的品牌事实；
- 产品分析不得读取兄弟产品；
- 竞品只作为产品比较参考；
- 联网结果只作为带来源的分析参考，不自动写回任何输入字段；
- 某维度依据不足时输出“信息不足”，不能补写事实。

### 6.3 状态

后端状态只保留：

- `queued`；
- `analyzing`；
- `review_required`；
- `confirmed`；
- `failed`。

用户界面分别显示“等待分析、分析中、待确认、已完成、分析失败”。开始操作需要幂等，连续点击不得创建重复批次。

## 7. 洞察结果与确认

品牌输出六要素，产品输出 BFABEWW 的 F、A、B、E、W、W；Base 只用于检查输入，不输出结论。

每个洞察项最少保存：

- 结论正文；
- 支撑状态：依据充分、部分支持、信息不足或存在冲突；
- 使用的输入字段名称；
- 联网参考链接；
- 缺失或冲突说明；
- 用户审核后的正文。

审核页面同时展示品牌及所有产品结果。客户可以修改洞察，但修改不写回品牌或产品事实字段。一次提交确认全部结果，并记录确认人、确认时间和输入快照版本。

确认后洞察不能日常随意改写。用户修改品牌或产品信息时，系统只提示“当前洞察未包含最新信息”并提供“更新洞察”按钮；用户不更新时继续使用原认知基准。

## 8. 最小数据与模块调整

### 8.1 继续复用

- `brands`：品牌结构化事实；
- `brand_products`：产品结构化事实；
- `brand_competitors`：选填竞品；
- `brand_knowledge_files`：原始附件；
- `background_jobs`：后台任务执行；
- 现有三步新建向导和保存接口；
- 现有统一大模型适配器、结构校验和后台 worker 模式。

### 8.2 最少新增

只新增两个业务结构：

1. `cognition_runs`：保存品牌、输入快照、状态、错误、模型版本及确认信息；
2. `cognition_insights`：保存批次、品牌或产品归属、模型类型、洞察 JSON、草稿/确认状态和当前版本。

现有附件记录增加可空的 `product_id`。表单中的结构化品牌和产品字段就是本版事实档案，不新建通用事实表、外部参考表、事实关系表或材料事实表。

### 8.3 认知建立模块对页面只提供四个行为

- 预检并开始分析；
- 读取批次状态和结果；
- 重试失败批次；
- 一次确认当前批次。

页面不自行复制服务端预检、快照、版本和幂等规则。

## 9. 实现前项目差距

- 新建品牌目前只校验品牌名称，缺少分析前预检；
- 行业和产品默认值仍带健身、餐饮、课程等本地生活语义；
- 产品缺少场景、优势、可解决问题、定量信息、证据、限制和其他信息；
- `price` 仍在核心产品表单；
- 附件只关联品牌，且“已生效、提取事实”等文案与真实能力不符；
- 没有品牌六要素与产品 BFABEWW 的独立任务和结构化结果；
- 没有认知分析批次、进度、重试、统一审核确认和当前版本；
- 现有检测分析会混合品牌和产品输入，不能直接当作认知建立逻辑复用。

## 10. 已执行的开发任务

### 任务 1：数据字段与迁移

- 为品牌、产品和附件补充上述最小字段；
- 新增认知批次和认知洞察表；
- 更新 TypeScript 类型和数据读写映射；
- 保持现有数据可读取，`price`、`city`、`stores` 不删除。

### 任务 2：统一预检

- 建立服务端唯一预检规则；
- 前端复用同一规则做即时提示；
- 返回字段级、分组化错误；
- 增加通过、缺失、重复名称和错误网址测试。

### 任务 3：调整新建品牌向导

- 保留“品牌—产品—竞品”三步；
- 替换本地生活行业选项和产品默认值；
- 增加品牌、产品字段；
- 竞品保持选填和可跳过；
- 最后一步触发保存、预检和分析任务。

### 任务 4：资料静态管理

- 支持品牌或产品归属；
- 展示上传元数据并支持下载、删除；
- 移除解析、事实数量和“已生效”相关文案与假状态；
- 不建设解析 worker。

### 任务 5：认知分析后台任务

- 增加品牌六要素和产品 BFABEWW 两种模型任务；
- 固定输入快照并严格隔离品牌、产品和竞品输入；
- 接入结构校验、联网参考、失败状态和原快照重试；
- 保证开始请求幂等。

### 任务 6：进度、审核与一次确认

- 增加批次进度页；
- 同页展示品牌和所有产品洞察；
- 支持客户修改洞察；
- 一次确认并建立当前版本；
- 事实变更后显示“更新洞察”，不自动更新。

### 任务 7：测试与验收

- 覆盖创建、选填竞品、预检、后台状态、重试和一次确认；
- 验证品牌不读取产品事实、产品不读取兄弟产品；
- 验证资料不参与分析；
- 验证洞察修改不改变事实字段；
- 运行类型检查、单元测试和关键真实流程测试。

## 11. 本版本不做

- 材料解析和自动事实提取；
- AI 自动补全并写回品牌或产品字段；
- 复杂事实图谱和证据关系表；
- 竞品认知模型；
- 部分产品分批确认；
- 营销内容生成；
- GEO 检测、认知偏差和持续运营；
- 库存、价格、订单和履约管理。
